一场关于唯品会是否上飞书的圆桌讨论

把 IT 的真实顾虑抛出来，大家一起聊聊 AI 时代的组织协同底座。

7 位成员在线讨论中
主持人19:30

今天不是说服唯品会上飞书，而是认真听懂唯品会 IT 部门的想法。

我们刚和唯品会 IT 团队聊完，他们提出了很多专业顾虑：自研 IM 深度承载业务、迁移成本不低、现有系统可控、安全和数据边界必须谨慎，他们也已经在探索自己的 AI Agent 和 MCP 方案。

所以请各位从自己的经验出发，一起拆拆看：IT 的顾虑哪些该尊重？哪些可能低估了未来？飞书真正可能帮唯品会解决的，不是“换工具”，而是什么？

IM 深度耦合 迁移成本 自研可控 安全边界 Agent / MCP
马化腾19:31

先尊重 IT 的谨慎，但别把耦合误认为稳定。

IM 对一家业务和系统高度复杂的企业来说，不只是聊天软件，它往往长着审批、机器人、系统通知、业务协作，一旦深度耦合，迁移确实不能拍脑袋。

但业务长在 IM 上，不一定代表系统稳，也可能代表架构分层不够清楚。飞书不一定要一上来替换所有 IM，可以先从会议、文档、知识沉淀这些低风险高收益场景切进去。先让价值被看见，再谈更大范围迁移。

张一鸣19:32

问题不是 IM，而是 AI 能不能消费企业上下文。

IT 团队现在评估的是“飞书作为 IM，值不值得替换现有 IM”。但飞书真正的价值可能不是 IM，而是统一上下文。

消息、文档、会议、知识库、任务如果分散在不同系统里，AI 拿到的是碎片；如果沉淀在统一底座里，AI 才能理解组织正在发生什么。唯品会如果要做 AI，不只是要有模型和 Agent，还要有可被 AI 消费的企业上下文。

马斯克19:33

别只保护系统，要回到知识流动效率。

我会问一个第一性原理问题：唯品会未来真正要优化的是什么？不是某个系统成本，而是组织决策速度、知识流动速度、业务创新速度。

自研可控很重要，但自研也会带来惯性。安全、迁移、可控都可以通过 POC 验证；但如果因为这些问题，完全不去验证新的协同范式，那风险反而更大。

乔布斯19:34

员工不是抗拒变化，而是还没看到更好的体验。

好的工具不是让人学习更多按钮，而是让工作自然发生：一次会议自动变成纪要和任务，一段讨论自然沉淀成知识，一个业务问题能被上下文直接回答。

如果飞书只是“另一个软件”，那没必要换；但如果它让唯品会的人少开会、少找资料、少在系统之间切换，那它就不是工具替换，而是体验升级。

马云19:35

迁移成本要算，不变的成本也要算。

IT 算迁移成本是应该的，但公司管理层还要算另一笔账：不变的成本。很多企业当年上云，也觉得自建机房安全、可控、便宜。但后来真正拉开差距的，不是省了多少服务器钱，而是谁更快获得弹性、更快试错、更快创新。

唯品会今天讨论飞书，也不只是办公工具，而是 AI 时代组织能力怎么升级。管理层要看的不是“换不换 IM”，而是“这件事会不会让唯品会跑得更快”。

黄仁勋19:36

Agent 需要统一底座，不只是管道拼接。

从 AI 基础设施角度看，Agent 不是孤立存在的。它需要数据、权限、上下文、工作流和反馈闭环。

MCP、OpenClaw、自研 Agent 当然可以做，但如果底层知识分散在多个系统里，Agent 每次都要跨系统拼上下文，效率和效果都会受影响。飞书如果能成为企业协同的统一上下文层，AI 能力才会越用越强。

主持人19:37

所以，不是要否定 IT，而是把问题往上提一层。

IT 看到的是系统迁移风险，公司管理层需要看到的是组织升级机会。短期看，飞书不应被包装成“替换唯秘 / 替换 IM”；更合理的切入是：围绕唯品会真实业务，选几个低风险、高价值的场景做样板间。

如果样板间跑不出价值，那就说明飞书不该硬推；但如果跑出了价值，唯品会看到的就不是一个工具，而是一套 AI 时代组织协同的新底座。
